# DB 04 — 제약조건 (Constraint)

## 제약조건이란

- 테이블에 들어가는 데이터를 규칙으로 관리하는 장치이다.
- 잘못된 데이터, 중복된 데이터, 엉뚱한 데이터가 들어가지 않도록 막는 안전장치이다.

**왜 필요할까?**
- 존재하지 않는 부서번호로 사원을 등록하면 안 된다.
- 같은 사람을 두 번씩 저장하면 안 된다.
- 주민등록번호나 학번처럼 중복되면 안 되는 값은 반드시 한 번만 존재해야 한다.

이런 것들을 자동으로 체크해주는 것이 제약조건이다.

**제약조건의 종류**
- 기본키(Primary Key)
- 외래키(Foreign Key)
- 고유키(Unique Key)
- 그 외: NOT NULL, CHECK 등

**정리**: 제약조건은 잘못되거나 중복되는 데이터가 테이블에 들어가지 못하도록 막는 규칙이다. 이어서 대표적인 제약조건인 기본키, 고유키, 외래키를 하나씩 살펴본다.

---

## 기본키 (Primary Key, PK)

- 테이블에서 각 행(레코드)을 구별하는 기준 컬럼이다.
- 쉽게 말해서 이 값을 보면 어떤 행인지 딱 하나만 찾아낼 수 있는 식별자이다.

**예시**
- 학생 테이블 : 학번
- 사원 테이블 : 사원번호(empno)
- 상품 테이블 : 상품코드(product_id)

**기본키의 특징**
- 테이블당 딱 하나만 지정 가능하다.
- 기본키 컬럼은 절대 중복될 수 없다. (중복 금지)
- 기본키 컬럼은 NULL을 가질 수 없다. (빈 값 금지)
- 즉, 유일하고 반드시 있는 값이다.

**예시 테이블 (학생(student) 테이블 설계)**
- `student_no` : 학번 (기본키)
- `major` : 전공

학생 번호는 절대 중복되면 안 되고, 반드시 있어야 한다. 그래서 `student_no`를 기본키로 설정한다.

```sql
CREATE TABLE student (
   student_no INT PRIMARY KEY,  -- 기본키
   name VARCHAR(50),
   major VARCHAR(50)
);
```

- `PRIMARY KEY`를 붙이면 `student_no`가 이 테이블의 기본키가 된다.
- 같은 `student_no`로 INSERT 하려고 하면 오류가 난다.
- `student_no`에 NULL을 넣으려고 해도 오류가 난다.

**정리**: 기본키는 테이블당 하나만 존재하며, 중복과 NULL을 모두 허용하지 않는 대표 식별자다. 이어서 기본키와 비슷하지만 여러 개 지정할 수 있는 고유키를 살펴본다.

---

## 고유키 (Unique Key, UNIQUE)

- 해당 컬럼의 값이 중복되지 않게 관리하는 제약조건이다.
- 즉, 그 컬럼에는 같은 값이 두 번 들어갈 수 없다.

**기본키와의 공통점**
- 둘 다 중복을 허용하지 않는다. (Primary Key, Unique 모두 값이 유일해야 한다.)

**기본키와의 차이점**

1) NULL 허용 여부
- 기본키: NULL 허용 안 됨
- 고유키: NULL 허용 가능 (DBMS마다 약간 차이 있지만 MySQL, Oracle 모두 일반적으로 UNIQUE 컬럼에 NULL 가능)
- 즉, 고유키는 값이 있으면 중복되면 안 되고, NULL은 여러 개 있어도 괜찮다고 이해해도 된다.

2) 개수 제한
- 기본키 : 테이블당 딱 1개
- 고유키 : 테이블당 여러 개 만들 수 있다.

3) 역할
- 기본키 : 테이블의 대표 식별자
- 고유키 : 대표 식별자는 아니지만, 이 값 역시 중복되면 안 됨을 보장

**예시 비유 (학생 테이블)**
- 기본키 : 학번(student_no)
- 고유키 : 이메일(email)

학번은 테이블의 대표 키이고, 이메일도 한 학생만 가지고 있어야 하니 중복되면 안 된다. 하지만 학번처럼 대표 식별자는 아닐 수 있다.

```sql
CREATE TABLE member (
  member_id INT PRIMARY KEY,   -- 기본키
  username VARCHAR(30) UNIQUE, -- 고유키
  email VARCHAR(100) UNIQUE,   -- 고유키
  phone VARCHAR(20)
);
```

- `member_id` : 테이블 전체에서 하나뿐인 대표 키
- `username` : 아이디이므로 중복되면 안 됨 (UNIQUE)
- `email` : 이메일도 보통 중복 불가 (UNIQUE)

고유키는 여러 개 둘 수 있다.

**언제 UNIQUE를 쓰는가?**

로그인 ID, 이메일, 주민등록번호, 사업자등록번호처럼 유일해야 하는 값에 많이 사용한다.

**정리**: 고유키는 기본키처럼 중복을 허용하지 않지만 NULL은 허용되고, 한 테이블에 여러 개 둘 수 있다는 점에서 기본키와 다르다. 이어서 두 테이블 사이의 관계를 표현하는 외래키를 살펴본다.

---

## 외래키 (Foreign Key, FK)

- 외래키는 다른 테이블의 기본키(또는 고유키)를 참조하는 컬럼이다. 즉 이 컬럼의 값은 반드시 다른 테이블에 이미 존재하는 값만 넣을 수 있다.
- 이걸 통해 두 테이블 사이의 관계를 표현한다.

**예시**
- `dept` 테이블 : 부서 정보 (부서번호 deptno, 부서명 dname)
- `emp` 테이블 : 사원 정보 (사원번호 empno, 이름 ename, 부서번호 deptno)

`emp.deptno`는 `dept` 테이블의 `deptno`를 참조하는 외래키가 된다.

**외래키의 특징**
- 다른 테이블의 기본키(또는 Unique 키)를 참조한다.
- 참조되는 테이블(부모 테이블)에 없는 값은 넣을 수 없다.
- 잘못된 부서번호, 잘못된 회원번호 같은 고아 데이터를 막아준다.

**부모 테이블과 자식 테이블**
- 부서 테이블 dept (부모)
- 사원 테이블 emp (자식)

부모 테이블: dept
- `deptno` (부서번호, 기본키)
- `dname` (부서명)

자식 테이블: emp
- `empno` (사원번호, 기본키)
- `ename` (이름)
- `deptno` (부서번호, 외래키 → dept.deptno 참조)

```sql
-- 부모 테이블(dept)
CREATE TABLE dept (
 deptno INT PRIMARY KEY,
 dname VARCHAR(50)
);

-- 자식 테이블(emp)
CREATE TABLE emp (
 empno INT PRIMARY KEY,
 ename VARCHAR(50),
 deptno INT,
 FOREIGN KEY (deptno) REFERENCES dept(deptno)
);
```

- `deptno`는 dept 테이블의 기본키다.
- `emp.deptno`는 `dept.deptno`를 참조하는 외래키다.
- dept 테이블에 없는 `deptno`로 emp에 INSERT 하면 오류가 발생한다.

**외래키가 왜 중요한가?**

1) 데이터 일관성 유지
- 예를 들어 dept에 10, 20번 부서만 있는데 emp에 `deptno = 30`으로 INSERT 하면 말이 안 된다.
- 외래키가 없으면 이런 잘못된 데이터가 들어갈 수 있다.
- 외래키를 걸어두면 DB가 자동으로 막아준다.

2) 조인(JOIN)의 기준이 된다
- emp와 dept를 JOIN 할 때도 대부분 `emp.deptno = dept.deptno`가 기준으로 묶는다.

**외래키와 삭제/수정 규칙**

부모 테이블에서 데이터를 삭제하면, 그 값을 참조하던 자식 테이블의 데이터는
- 삭제를 막는다 (기본)
- 함께 삭제한다 (`ON DELETE CASCADE`)

예를 들어 부서 10번을 삭제하면 부서 10에 속한 사원들도 함께 삭제할 것인지, 아니면 부서에 사원이 남아 있으니 부서를 삭제 못 하게 막을지 이런 동작을 외래키 옵션으로 조절한다.

**정리**: 외래키는 다른 테이블의 기본키/고유키를 참조해 잘못된 데이터가 들어가는 것을 막고 JOIN의 기준이 되며, `ON DELETE CASCADE` 같은 옵션으로 부모 데이터 삭제 시 자식 데이터를 어떻게 처리할지 조절할 수 있다.
