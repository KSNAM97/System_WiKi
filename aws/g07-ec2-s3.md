# AWS EC2와 S3 연동하기

## 1. 개요

EC2 인스턴스에서 S3 버킷에 파일을 업로드·다운로드하려면 인증 수단이 필요하다. Access Key를 인스턴스에 직접 저장하는 방식은 키 유출 위험이 있으므로, [EC2 배포](t02-ec2-deployment.md)의 [12. EC2 권한 부여](t02-ec2-deployment.md#12-ec2-권한-부여)에서 설명한 대로 **IAM 역할(Role)**을 EC2에 부여하는 방식을 사용한다. 이 문서에서는 S3 버킷 생성부터 IAM 역할 연결, AWS CLI로 파일을 주고받는 실습, User Data를 이용한 자동 배포까지 다룬다.

## 2. S3 버킷 생성

콘솔 절차는 [Getting started with Amazon S3(AWS 공식 문서)](https://docs.aws.amazon.com/AmazonS3/latest/userguide/GetStartedWithS3.html)를 참고한다. S3 콘솔의 [버킷] 메뉴에서 [버킷 만들기]를 클릭한다.

- **버킷 이름**: 전역적으로 고유해야 하므로 계정 ID나 임의 문자열을 포함해 작성 (예: `my-bucket-<임의문자열>-ap-northeast-2`)
- **AWS 리전**: EC2 인스턴스와 동일한 리전 선택 (예: 아시아 태평양(서울)) — 버킷 생성 후에는 리전을 변경할 수 없다.
- **객체 소유권(Object Ownership)**: 별도 요구사항이 없다면 기본값 **ACL 비활성화됨(버킷 소유자 강제 적용)** 유지
- **퍼블릭 액세스 차단(Block Public Access) 설정**: 별도 요구사항이 없다면 기본값(4가지 모두 활성화) 유지

버킷 생성 후, 필요하다면 콘솔에서 [업로드] 버튼으로 폴더 구조(`image/`, `file/` 등)를 만들고 테스트 파일을 올려 둔다.

## 3. S3 접근 권한을 가진 IAM 역할 생성

콘솔 절차는 [IAM roles for Amazon EC2(AWS 공식 문서)](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html)를 참고한다. IAM 콘솔의 [역할] 메뉴에서 [역할 생성]을 클릭한다.

1. **신뢰할 수 있는 엔터티 유형**: AWS 서비스
2. **사용 사례**: EC2
3. **권한 정책**: `AmazonS3ReadOnlyAccess`(읽기만 필요한 경우) 또는 `AmazonS3FullAccess`(업로드까지 필요한 경우)를 검색해 선택. 특정 버킷으로만 범위를 좁히고 싶다면 [정책 생성]에서 `Resource`를 해당 버킷 ARN으로 제한한 커스텀 정책을 만들어 연결한다.
4. **역할 이름**: 예) `EC2-S3-Access-Role`

역할을 생성하면 콘솔이 동일한 이름의 **인스턴스 프로필(Instance Profile)**을 자동으로 함께 만든다 — EC2는 역할을 이 인스턴스 프로필 단위로 연결한다.

## 4. EC2 인스턴스에 IAM 역할 연결

새로 생성하는 인스턴스라면 [인스턴스 시작] 단계의 **고급 세부 정보 → IAM 인스턴스 프로필**에서 앞서 만든 역할을 선택한다.

이미 실행 중인 인스턴스에 연결하려면, EC2 콘솔에서 인스턴스를 선택 → [작업] → [보안] → [IAM 역할 수정]에서 역할을 지정한다. 인스턴스 하나에는 역할을 1개만 연결할 수 있으며(동일한 역할을 여러 인스턴스에 연결하는 것은 가능), 재부팅 없이 즉시 적용된다.

## 5. 실습: AWS CLI로 S3 파일 주고받기

IAM 역할이 연결된 EC2 인스턴스에 접속해 아래 명령을 실행한다. Access Key 등록 없이 바로 동작한다. 명령어 전체 목록은 [AWS CLI s3 명령어(AWS 공식 문서)](https://awscli.amazonaws.com/v2/documentation/api/latest/reference/s3/index.html)를 참고한다.

```bash
# 버킷 내 객체 목록 조회 (폴더별)
aws s3 ls s3://my-bucket-name/image/
aws s3 ls s3://my-bucket-name/file/

# 버킷 전체를 재귀적으로 조회
aws s3 ls s3://my-bucket-name --recursive
```

```bash
# S3 -> EC2 파일 다운로드
aws s3 cp s3://my-bucket-name/index.html .
```

```bash
# S3 <- EC2 파일 업로드
touch newFile.txt
aws s3 cp newFile.txt s3://my-bucket-name/
```

```bash
# S3 <-> EC2 동기화 (달라진 파일만 전송)
aws s3 sync s3://my-bucket-name .
```

`cp`는 지정한 파일 하나만 복사하고, `sync`는 두 위치를 비교해서 달라진 파일만 전송한다 — 파일 여러 개를 반복 배포할 때는 `sync`가 더 효율적이다.

## 6. 실습: User Data로 S3 콘텐츠 자동 배포

시작 템플릿(또는 인스턴스 시작 마법사)의 User Data에 아래 스크립트를 등록하면, 인스턴스가 최초 부팅될 때 S3에 올려 둔 정적 파일을 자동으로 웹 루트에 배포한다.

```bash
#!/bin/bash
sudo -s
dnf install httpd -y
service httpd start
chkconfig httpd on
aws s3 cp s3://my-bucket-name/index.html /var/www/html --region ap-northeast-2
```

이 방식은 AMI를 다시 굽지 않고도 S3에 새 버전의 정적 파일만 올려두면, 이후 새로 생성되는 인스턴스가 항상 최신 콘텐츠로 배포되는 장점이 있다. Auto Scaling 그룹과 함께 사용하면, 늘어나는 인스턴스마다 별도 작업 없이 동일한 최신 콘텐츠가 자동으로 적용된다.
